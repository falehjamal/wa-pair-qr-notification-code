WhatsApp Session Manager API

Production-ready multi-session WhatsApp API powered by Baileys, with real-time WebSocket updates, dual pairing methods, and session lifecycle management.

Node.js  ESM Express  4.x Baileys  6.x Socket.IO  4.x QR + Pairing Code

Overview

WhatsApp Session Manager adalah REST API yang memungkinkan Anda mengelola banyak sesi WhatsApp secara bersamaan. Setiap sesi memiliki lifecycle independen, autentikasi tersimpan di file system, dan update real-time melalui WebSocket.

Fitur Utama

  • Multi-Session — Kelola banyak sesi WhatsApp dalam satu server
  • Dual Pairing — Hubungkan via QR Code atau Pairing Code (notifikasi WhatsApp)
  • Real-time Updates — QR, status koneksi, pairing code via Socket.IO
  • Number Validation — Cek apakah nomor terdaftar di WhatsApp
  • Session Persistence — Autentikasi disimpan di file system, auto-reconnect saat restart
  • API Key Auth — Mendukung multiple API keys via header
  • Rate Limiting — Proteksi request berlebihan
  • Production Ready — Error handling, graceful shutdown, logging dengan Pino

Authentication

Semua endpoint di bawah /api/* memerlukan API key. Kirim API key melalui header x-api-key.

ℹ️
Jika variabel API_KEYS di .env dikosongkan, autentikasi akan di-bypass (berguna untuk development).

Contoh Header

x-api-key: your-api-key-1

Konfigurasi Multiple Keys

# .env
API_KEYS=key-satu,key-dua,key-tiga

Response Jika Tidak Terautentikasi

{
  "success": false,
  "message": "API key is required. Provide it via x-api-key header."
}

Base URL

Secara default, server berjalan di:

http://localhost:3000

Prefix untuk semua API session endpoint:

/api/session

Contoh URL lengkap:

http://localhost:3000/api/session/create

Response Format

Semua response API menggunakan format JSON yang konsisten:

✓ Success Response
{
  "success": true,
  "message": "Operation description",
  "data": { ... }
}
✗ Error Response
{
  "success": false,
  "message": "Error description"
}

Rate Limiting

API dilindungi oleh rate limiter untuk mencegah penyalahgunaan. Secara default:

  • Window: 15 menit (900.000 ms)
  • Max Requests: 100 per window per IP

Konfigurasi via environment variables:

RATE_LIMIT_WINDOW_MS=900000
RATE_LIMIT_MAX=100

Response saat limit tercapai: HTTP 429 Too Many Requests

Error Handling

API menggunakan HTTP status code standar:

Status Code Deskripsi
200Request berhasil
201Resource berhasil dibuat
400Bad Request — parameter tidak valid
401Unauthorized — API key tidak valid atau tidak ada
404Not Found — session/resource tidak ditemukan
429Too Many Requests — rate limit tercapai
500Internal Server Error — error di server
⚠️
Di production mode (NODE_ENV=production), pesan error detail disembunyikan dan diganti "Internal server error" untuk keamanan.

POST /api/session/create Buat sesi WhatsApp baru ▼

Description

Membuat sesi WhatsApp baru. Mendukung dua metode pairing: QR code (default) dan pairing code via notifikasi WhatsApp. Jika sessionId tidak dikirim, akan digenerate UUID otomatis.

Headers

HeaderValue
Content-Typeapplication/json
x-api-keyyour-api-key

Request Body

ParameterTypeRequiredDescription
sessionId string optional ID sesi (alfanumerik, -, _). Auto-generate UUID jika kosong.
pairingMethod string optional Metode pairing: "qr" (default) atau "code"
phoneNumber string required if code Nomor telepon format E.164 tanpa + (contoh: 628123456789). Wajib jika pairingMethod = "code".

cURL — QR Code Method

curl -X POST http://localhost:3000/api/session/create \
  -H "Content-Type: application/json" \
  -H "x-api-key: your-api-key" \
  -d '{"sessionId": "my-session", "pairingMethod": "qr"}'

cURL — Pairing Code Method

curl -X POST http://localhost:3000/api/session/create \
  -H "Content-Type: application/json" \
  -H "x-api-key: your-api-key" \
  -d '{"sessionId": "my-session", "pairingMethod": "code", "phoneNumber": "628123456789"}'

Response — 201 Created

{
  "success": true,
  "message": "Session created",
  "data": {
    "sessionId": "my-session",
    "pairingMethod": "qr",
    "message": "Session created. Listen to WebSocket for QR/pairing events."
  }
}

Errors

StatusCondition
400Invalid sessionId format
400Invalid pairingMethod (bukan "qr" atau "code")
400phoneNumber diperlukan tapi tidak ada (method "code")
400Format phoneNumber tidak valid
401API key tidak valid

WebSocket (Socket.IO)

Aplikasi menggunakan Socket.IO dengan dynamic namespaces untuk update real-time per sesi. Setiap sesi memiliki namespace sendiri berdasarkan session ID.

Connection

Untuk menerima event dari sesi tertentu, hubungkan ke namespace /{sessionId}:

// JavaScript (Browser)
import { io } from "socket.io-client";

const socket = io("http://localhost:3000/my-session");

socket.on("connect", () => {
  console.log("Connected to session namespace");
});

socket.on("disconnect", (reason) => {
  console.log("Disconnected:", reason);
});
ℹ️
Socket.IO dynamic namespaces menerima koneksi ke path apapun. Namespace otomatis dibuat berdasarkan session ID saat pertama kali client terhubung.

Events

Berikut adalah event yang di-emit oleh server ke client melalui namespace sesi:

qr

Dikirim saat QR code tersedia untuk di-scan. QR dikirim sebagai base64 data URL yang bisa langsung ditampilkan di <img> tag. Event ini dikirim berkali-kali (max 5x) jika QR tidak di-scan dan expired.

{
  "qr": "data:image/png;base64,iVBORw0KGg..."
}
pairing_code

Dikirim saat pairing code berhasil di-request (method: "code"). User harus memasukkan kode ini di WhatsApp: Linked Devices → Link with phone number.

{
  "code": "ABCD-EFGH",
  "phoneNumber": "628123456789"
}
connected

Dikirim saat sesi berhasil terhubung ke WhatsApp. Berisi informasi user yang terkoneksi.

{
  "user": {
    "id": "628123456789:42@s.whatsapp.net",
    "name": "John Doe"
  }
}
disconnected

Dikirim saat sesi terputus dari WhatsApp, baik karena logout, error, atau dihapus.

{
  "reason": "loggedOut"
}

Panduan Pairing Methods

Metode 1 — QR Code (Default)

Cara paling umum untuk menghubungkan WhatsApp:

  1. Buat sesi dengan pairingMethod: "qr" (atau kosongkan)
  2. Hubungkan ke WebSocket namespace /{sessionId}
  3. Terima event qr dan tampilkan QR code
  4. Scan QR code dari WhatsApp → Linked Devices → Link a Device
  5. Terima event connected saat berhasil
⚠️
QR code expire setelah ~60 detik. Server akan otomatis mengirim QR baru (max 5 kali). Jika semua QR expire, sesi akan dihapus.

Metode 2 — Pairing Code

Metode alternatif menggunakan kode 8 digit yang dimasukkan langsung di WhatsApp:

  1. Buat sesi dengan pairingMethod: "code" dan phoneNumber
  2. Hubungkan ke WebSocket namespace /{sessionId}
  3. Terima event pairing_code berisi kode 8 digit
  4. Di WhatsApp mobile: Linked Devices → Link a Device → Link with phone number instead
  5. Masukkan kode pairing
  6. Terima event connected saat berhasil
ℹ️
Pairing code lebih mudah untuk integrasi di mana user tidak bisa scan QR (misalnya CLI, bot setup, remote server). Kode dikirimkan sebagai notifikasi ke nomor WhatsApp yang dituju.

Configuration

Semua konfigurasi dilakukan melalui file .env. Berikut daftar lengkap variabel:

Variable Default Description
PORT 3000 Port server
HOST 0.0.0.0 Host binding (0.0.0.0 = semua interface)
API_KEYS empty API keys, pisahkan dengan koma. Kosongkan untuk disable auth.
CORS_ORIGIN * Allowed CORS origins
LOG_LEVEL info Pino log level (trace, debug, info, warn, error, fatal)
SESSIONS_DIR ./sessions Direktori penyimpanan data autentikasi sesi
RATE_LIMIT_WINDOW_MS 900000 Rate limit window dalam ms (default: 15 menit)
RATE_LIMIT_MAX 100 Max request per window per IP
NODE_ENV development Environment mode (production menyembunyikan detail error)

Contoh .env

# Server
PORT=3000
HOST=0.0.0.0

# Auth
API_KEYS=sk-live-abc123,sk-live-def456

# CORS
CORS_ORIGIN=https://myapp.com

# Logging
LOG_LEVEL=info

# Sessions
SESSIONS_DIR=./sessions

# Rate Limiting
RATE_LIMIT_WINDOW_MS=900000
RATE_LIMIT_MAX=100

Deployment

Quick Start

# Clone & install
git clone <repo-url>
cd nova-project
npm install

# Configure
cp .env.example .env
# Edit .env sesuai kebutuhan

# Run
npm start

# Development (with auto-reload)
npm run dev

PM2 (Production)

# Install PM2
npm install -g pm2

# Start with PM2
pm2 start server.js --name wa-session-manager

# Auto-restart on reboot
pm2 startup
pm2 save

# Monitor
pm2 logs wa-session-manager
pm2 monit

Docker

# Dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
# Build & Run
docker build -t wa-session-manager .
docker run -d \
  --name wa-session \
  -p 3000:3000 \
  -v wa-sessions:/app/sessions \
  --env-file .env \
  wa-session-manager

Nginx Reverse Proxy

server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
⚠️
Pastikan konfigurasi Nginx mendukung WebSocket (Upgrade dan Connection headers) agar Socket.IO berjalan dengan baik.
